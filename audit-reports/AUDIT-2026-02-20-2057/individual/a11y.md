## Fix 1 — Skip Navigation Link (High)

**WCAG:** 2.4.1 Bypass Blocks (Level A)  
**Location:** `src/app/layout.tsx`  
**Issue:** No skip-to-content link. Keyboard and screen reader users must tab through the entire navbar (DocVault link, Dashboard, Sign in/Sign up, UserButton) before reaching main content on every page.

**Fix pattern:**

```tsx
// Add as first focusable element inside <body>, before <Providers>
<a
  href="#main-content"
  className="sr-only focus:not-sr-only focus:absolute focus:top-4 focus:left-4 focus:z-[100] focus:px-4 focus:py-2 focus:bg-primary focus:text-primary-foreground focus:rounded-md"
>
  Skip to main content
</a>
```

Then add `id="main-content"` to the `<main>` element:

```tsx
<main id="main-content" className="min-h-[calc(100vh-4rem)]">{children}</main>
```

## Fix 2 — Icon-Only Buttons Without Accessible Names (Medium)

**WCAG:** 1.1.1 Non-text Content, 2.1.1 Keyboard (Level A)  
**Locations:** Multiple components

**Issue:** Icon-only buttons have no `aria-label`. Screen readers announce nothing meaningful; keyboard users cannot understand the action.

| File | Line | Context |
|------|------|---------|
| `src/components/upload-dialog.tsx` | 165–171 | Remove-file button (X icon) |
| `src/components/upload-dialog.tsx` | 175–186 | File picker button |
| `src/components/member-manager.tsx` | 260–268 | Remove member button |
| `src/components/member-manager.tsx` | 322–329 | Cancel invite button |
| `src/components/document-table.tsx` | 185–192 | Document actions dropdown trigger |

**Fix pattern:**

Add `aria-label` to each icon-only button:

```tsx
// upload-dialog.tsx — remove file
<Button
  variant="ghost"
  size="icon"
  className="h-8 w-8 shrink-0"
  onClick={() => setFile(null)}
  disabled={isUploading}
  aria-label="Remove selected file"
>
  <X className="h-4 w-4" />
</Button>

// upload-dialog.tsx — file picker
<button
  type="button"
  onClick={() => fileInputRef.current?.click()}
  className="..."
  aria-label="Select file to upload"
>

// member-manager.tsx — remove member
<Button
  variant="ghost"
  size="icon"
  ...
  aria-label={`Remove ${member.user?.name ?? 'member'} from team`}
>

// member-manager.tsx — cancel invite
<Button
  ...
  aria-label={`Cancel invite for ${invite.email}`}
>

// document-table.tsx — dropdown trigger
<Button
  variant="ghost"
  size="icon"
  className="h-8 w-8"
  aria-label={`Actions for ${doc.name}`}
>
```

## Fix 3 — Rename Dialog Input Without Label (Medium)

**WCAG:** 1.3.1 Info and Relationships, 3.3.2 Labels or Instructions (Level A)  
**Location:** `src/components/document-table.tsx` lines 229–239  
**Issue:** The rename document dialog uses an `<Input>` with no associated label. Screen readers cannot announce the purpose of the field.

**Fix pattern:**

```tsx
<DialogContent aria-describedby={undefined}>
  <DialogHeader>
    <DialogTitle>Rename Document</DialogTitle>
  </DialogHeader>
  <div className="space-y-2">
    <Label htmlFor="rename-doc-input">New name</Label>
    <Input
      id="rename-doc-input"
      value={newName}
      onChange={(e) => setNewName(e.target.value)}
      onKeyDown={(e) => {
        if (e.key === "Enter") handleRename();
      }}
      autoFocus
      aria-describedby="rename-doc-hint"
    />
    <p id="rename-doc-hint" className="sr-only">
      Enter the new document name
    </p>
  </div>
  ...
</DialogContent>
```

## Deferred Findings

The following were identified but not given full fix patterns (limit of 3 fixes):

- **Decorative SVG icons:** `FileText`, `Users`, `FolderOpen`, etc. in navbar and cards — add `aria-hidden="true"` when purely decorative.
- **Loading state announcements:** Upload dialog `isUploading` state — consider `aria-live="polite"` region or `aria-busy` on the form.
- **Select components:** Role selectors in `member-manager.tsx` lack `aria-label` on `SelectTrigger` when label is visually hidden.
- **Page titles:** Verify each route has a unique, descriptive `<title>` via Next.js metadata.
- **Sonner toasts:** Confirm Sonner uses `aria-live` for announcements (default is `polite`).
